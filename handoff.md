# Session Handoff: Lightweight Android Download Manager & Media Interceptor (1DM Alternative)

## 1. Intent & Context
- **Goal**: Architect and implement Siphon, a lean, open-source Android alternative to 1DM featuring multi-part chunked HTTP downloading, WebView media interception, in-memory host ad-blocking, zero-FFmpeg HLS stream extraction, and post-MVP torrent support.
- **Scope**: Core Android client architecture (Kotlin 2.x, Jetpack Compose, Room, OkHttp, WebView, Android built-in media/storage APIs) targeting API 29–35.

## 2. Settled Decisions (with Rationale)
- **HTTP Engine Concurrency & Adaptive Chunking**: Split downloads into clamped adaptive chunks (`max(4MB, totalBytes / 512)` capped at `32MB`, or `totalBytes / workerCount` for small files < 24MB) placed in a `ConcurrentLinkedQueue` pulled by `N` parallel workers (default 6, configurable 1–8). Default 2 concurrent active downloads globally (configurable 1–4) with 3 exponential-backoff retries per chunk (`1s`, `2s`, `4s` + `Retry-After` support) before transitioning to `WAITING_FOR_NETWORK` or `FAILED`.
- **Dual-Protocol OkHttp Strategy**: Force HTTP/1.1 (`Protocol.HTTP_1_1`, max 6–8 connections per host) for chunked file downloads; use default HTTP/2 client for HLS/probes sharing the connection pool.
- **Thread-Safe Positional Disk I/O**: Share a single `FileChannel` across all workers using positional `channel.write(buffer, position)` loops.
- **Checkpointer Ordering Invariant (Snapshot → Fsync → DB)**: Track `currentOffset` (`AtomicLong`) per chunk. Every 2–4 seconds, a single checkpointer coroutine snapshots all workers' `AtomicLong` offsets and in-memory `DONE` states *before* calling `channel.force(false)`, then commits that snapshot to Room (`download_chunks`) *after* `force()` returns. On boot, any `IN_FLIGHT` chunk resets to `PENDING` and resumes from its persisted `currentOffset`.
- **Validation, Single-Stream Fallback & Safe Resumption**: Resume using `If-Range: <etag>` (strong ETags only) or `Last-Modified`; validate `Content-Range` on every HTTP 206. For servers without `Accept-Ranges: bytes` or unknown `Content-Length` (`-1`), insert a single `ChunkEntity(index=0, endOffset=-1)` with `isResumable=false` on `DownloadEntity` (truncating channel to 0 on retry/reboot).
- **Expiring CDN URL Rebind & Overlap Verification**: Persist `sourcePageUrl` in `downloads`. When a paused download hits HTTP 403/410, tapping Resume opens `sourcePageUrl` in WebView in explicit "Update Link" rebind mode. Before adopting the new URL + ETag, verify `Content-Length == totalBytes` AND byte-compare a 4KB `Range: bytes=0-4095` sample against local disk.
- **Credential Hygiene**: Store per-download `headersJson` (`Cookie`, `Referer`, `User-Agent`) in the `downloads` table with `android:allowBackup="false"` and `dataExtractionRules` excluding the DB; immediately set `headersJson = NULL` upon `COMPLETED` or `CANCELLED`.
- **Passive Media Sniffing & Dedup**: Keep `shouldInterceptRequest` strictly passive for non-ads (return `null` so Chromium loads normally). Dedup candidate URLs by normalized URL (stripping byte-range query params) in an LRU set; skip probing `.ts`/`.m4s` segments when a parent `.m3u8`/`.mpd` manifest was already captured on the same page; fetch/parse `.m3u8` directly via background OkHttp instead of `0-0` probing.
- **Suffix-Matching Host Blocker**: Pre-sized `HashSet<String>` loaded lazily on `Dispatchers.Default` from a pre-stripped lowercase domain asset list (1 domain per line), using domain suffix slicing (`a.b.ads.com` -> `b.ads.com` -> `ads.com`) in `shouldInterceptRequest` and `shouldOverrideUrlLoading`.
- **Zero-FFmpeg HLS Sliding-Window Assembly & Remux**: Key chunks by `(downloadId, trackIndex, chunkIndex)`. Decrypt AES-128 segments via `CipherInputStream` into `seg_<track>_<idx>.tmp`. As contiguous segments finish, append directly into `track_<trackIndex>.tmp`, record cumulative byte offset in `chunk.endOffset`, `channel.force(false)`, mark chunk `MERGED` in Room, and delete the segment file immediately (avoiding 3x disk amplification). On crash resume, truncate `track_<trackIndex>.tmp` to the last `MERGED` offset. Remux completed track files into `.mp4` via a single `MediaExtractor` -> `MediaMuxer` pass (falling back to `.ts` if codec is unsupported by muxer).
- **Storage & Pre-flight Strategy**: Store `destinationUri` (`content://` String) + `displayName` in `downloads` using `MediaStore.Downloads` (`IS_PENDING=1`, `DATE_EXPIRES` +30d) or SAF document trees; call `contentResolver.delete(uri, null, null)` on cancel/reset to prevent orphan pending files. Run `StatFs.availableBytes` and filesystem check (`/proc/mounts` / `Os.fstatvfs`) to enforce the 4GB FAT32 limit and warn/cap parallel chunk distance on non-sparse external FAT/exFAT mounts.
- **Background Execution**: Single `dataSync` Foreground Service for v1 implementing Android 15's two-arg `onTimeout(int, int)` to `force(false)`, checkpoint DB to `PAUSED`, and post a tap-to-resume notification. Defer UIDT `JobService` and `full`/`slim` Torrent flavors (`libtorrent4j`) to post-MVP (Milestone 8, YAGNI).

## 3. Current State & Artifacts
- **Status**: Milestones 0, 1, 2, and 3 completed:
  - Dual-protocol OkHttp factory & header serializer: `NetworkClients`, `HeadersCodec`
  - Range/HEAD metadata prober + 4KB overlap URL rebind verifier: `MetadataProber`
  - Multi-worker positional `FileChannel` downloader with pre-force snapshot checkpointer, 206 offset validation, 403/410 auth expiry handling, and single-stream fallback: `ChunkQueueEngine`
  - `MediaStore.Downloads` (`IS_PENDING = 1`, `+30d` `DATE_EXPIRES`) + SAF document tree provider & `Os.fstatvfs` / `/proc/mounts` FAT32/non-sparse pre-flight check: `DownloadStorageProvider`, `FilesystemPreflight`
  - Foreground execution service with `sample(250ms)` progress notification, Pause/Resume/Cancel `PendingIntent` actions, `ConnectivityManager.NetworkCallback` auto-resume, and Android 14/15 `onTimeout` checkpointing: `DownloadForegroundService`
  - Ready for Milestone 4 (`FastHostFilter` in-memory ad-blocker) or minimal test UI activity.
